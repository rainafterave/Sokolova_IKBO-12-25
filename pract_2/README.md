# Практическая работа №2. Граф зависимостей Cargo

Вариант 23, все пять этапов.
Соколова Милена, группа ИКБО-12-25.

Программа показывает, от каких других пакетов зависит выбранный пакет Rust.
Она читает настройки из INI, получает зависимости и строит граф:
стрелка идет от пакета к его зависимости. Результат выводится в формате
PlantUML. Можно также получить SVG-картинку.

Данные реальных пакетов программа читает сама из sparse-индекса Cargo
средствами стандартной библиотеки Python. Для проверки без интернета есть
тестовые графы с пакетами A, B, C и так далее.

## Что сделано

1. Настройки из INI, вывод всех параметров и обработка ошибок.
2. Чтение прямых зависимостей настоящих пакетов Rust/Cargo.
3. Обход графа в ширину (BFS) без рекурсии, ограничение глубины,
   исключение пакетов по подстроке и обработка циклов.
4. Вывод порядка обработки: сначала зависимости, затем использующие их
   пакеты. Для циклического графа выводится сообщение, что такого порядка нет.
5. Вывод PlantUML и примеры диаграмм трех реальных пакетов.
   Результаты сравнены с настоящим Cargo.

## Как запустить

Нужен Python 3.10 или новее. Дополнительные библиотеки и сборка не нужны.
Откройте терминал в папке `pract_2` и выполните:

```powershell
.\run.bat
```

По умолчанию используется тестовый граф, поэтому интернет не требуется.
Будет выведен текст PlantUML. На Linux/macOS запуск: `sh run.sh`.

## Настройки

Пример файла `configs/test.ini`:

```ini
[analysis]
package = A
repository = ../tests/graphs/diamond.txt
test_mode = true
max_depth = 10
filter =
```

| Параметр | Для чего нужен |
|---|---|
| `package` | Имя пакета. В тестах — большие латинские буквы. Для Cargo можно указать версию: `csv@1.4.0` |
| `repository` | Путь к тестовому графу или URL sparse-индекса, например `https://index.crates.io` |
| `test_mode` | `true` — тестовый файл, `false` — реальный репозиторий |
| `max_depth` | Максимальная глубина: 0 — только корень, 1 — прямые зависимости |
| `filter` | Пакеты с этой подстрокой в имени исключаются вместе с обходом их ветки. Пустое значение отключает фильтр |

Путь к тестовому файлу отсчитывается от папки INI. Фильтр учитывает регистр.
Неверные имена, отсутствующие файлы, неправильные URL, отрицательная глубина
и другие ошибки настроек сопровождаются сообщением.

## Запуск этапов

Параметр `--config` выбирает INI, `--stage` — этап от 1 до 5.
По умолчанию выбран этап 5.

```powershell
.\run.bat --config configs/test.ini --stage 1
.\run.bat --config configs/test.ini --stage 2
.\run.bat --config configs/test.ini --stage 3
.\run.bat --config configs/test.ini --stage 4
.\run.bat --config configs/test.ini --stage 5
```

На этапе 1 выводятся настройки, на этапе 2 — прямые зависимости,
на этапе 3 — весь исследованный граф с номерами уровней,
на этапе 4 — порядок обработки, на этапе 5 — текст диаграммы.

У общего пакета сохраняются все входящие связи, но повторный обход
выполняется только при необходимости. Циклы не вызывают зацикливания.
Порядок и найденные циклы относятся к части графа в пределах выбранной
глубины и фильтра. Пакеты на последнем уровне показаны без дальнейшего обхода.

## Примеры

Ограничение глубины и фильтр:

```powershell
.\run.bat --config configs/depth.ini --stage 3
.\run.bat --config configs/filter.ini --stage 3
```

Циклический граф можно вывести и нарисовать. Запрос порядка завершится
понятной ошибкой:

```powershell
.\run.bat --config configs/cycle.ini --stage 3
.\run.bat --config configs/cycle.ini --stage 4
```

Реальный пакет и сохранение диаграммы:

```powershell
.\run.bat --config configs/regex.ini --output output/regex.puml
```

`--output` сохраняет текст PlantUML. Чтобы дополнительно получить SVG,
добавьте `--svg`. При этом описание графа отправляется официальному
серверу PlantUML; нужен доступ в интернет:

```powershell
.\run.bat --config configs/regex.ini --output output/regex.puml --svg output/regex.svg
```

`--help` показывает справку. Коды завершения: 0 — успех, 1 — ошибка данных
или сети, 2 — неверные параметры командной строки.

## Готовые диаграммы и сравнение

Диаграммы уже сохранены; их можно открыть без повторного анализа:

- [csv 1.4.0](examples/csv.svg) — [текст PlantUML](examples/csv.puml).
- [regex 1.13.1](examples/regex.svg) — [текст PlantUML](examples/regex.puml).
- [serde_json 1.0.154](examples/serde_json.svg) — [текст PlantUML](examples/serde_json.puml).

[Отчет сравнения с Cargo](examples/comparison.md) содержит фактические
результаты. Для трех выбранных пакетов совпали вершины и ребра графа.
Рядом сохранен штатный вывод `cargo tree` и журнал скачивания пакетов.

Наш порядок ставит зависимости раньше основного пакета. Cargo рисует
дерево от основного пакета, а скачивает архивы с учетом сети и кеша.
Поэтому порядок строк и физического скачивания может отличаться.

Для реальных пакетов учитываются normal/build-зависимости, default features
и возможности, запрошенные зависимостями. Условные зависимости объединены
для всех платформ; dev-зависимости исключены. Для сравнения используется
`cargo tree --target all --edges normal,build`.

Выбор версии упрощен: берется максимальная подходящая версия, исключая
yanked и неподходящие prerelease. Полный решатель Cargo, Cargo.lock,
ограничения rust-version и разделение features в resolver v2/v3
не воспроизводятся. На других пакетах это может приводить к расхождениям.

Если Cargo установлен, сравнение можно повторить:

```powershell
py -3 scripts/compare_cargo.py
```

Только этот проверочный скрипт обращается к Cargo. Сам анализатор его
не запускает.

## Тестовые графы

Формат: слева пакет, справа его прямые зависимости. Все пакеты должны
быть объявлены, в том числе пакеты без зависимостей:

```text
A: B C
B: D
C: D
D:
```

Это граф-ромб: A зависит от B и C, а оба они зависят от D.
Порядок обработки: `D -> B -> C -> A`.
В папке `tests/graphs` также есть цепочка, цикл, петля,
одиночный пакет, сложный граф и пример с отсутствующей вершиной.

## Проверки

Из папки `pract_2`:

```powershell
py -3 -m unittest discover -s tests -v
.\scripts\demo_stages.bat
.\scripts\test_graphs.bat
.\scripts\test_errors.bat
```

Тесты не требуют интернета. Они проверяют настройки, диапазоны версий,
формат Cargo, features, BFS, глубину, фильтр, циклы, порядок и PlantUML.
Отдельно проверяется цепочка из 1501 пакета: обработка работает без рекурсии.
Сообщения об ожидаемых ошибках в командных сценариях — часть проверки.

Повторное получение трех реальных диаграмм с интернетом:

```powershell
.\scripts\demo_real.bat
```

## Папки и файлы

- `src` — код программы: настройки, версии, репозитории, граф и PlantUML.
- `configs` — готовые настройки; `configs/errors` — примеры неверных настроек.
- `tests` — автоматические проверки и тестовые графы.
- `scripts` — демонстрации, проверки и сравнение с Cargo.
- `examples` — три готовые диаграммы и отчет сравнения.
- `run.bat`, `run.sh` — запуск в Windows и Linux/macOS.

В `src` файл `main.py` запускает анализ, `config.py` читает INI,
`registry.py` получает записи Cargo, `semver.py` выбирает версии,
`features.py` раскрывает возможности пакетов, `test_repository.py` читает
тестовый граф, `graph.py` выполняет BFS и определяет порядок,
`plantuml.py` формирует диаграмму, `models.py` содержит общие типы данных.

Форматы сверены с официальной документацией:
[индекс Cargo](https://doc.rust-lang.org/cargo/reference/registry-index.html),
[версии](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html),
[features](https://doc.rust-lang.org/cargo/reference/features.html),
[cargo tree](https://doc.rust-lang.org/cargo/commands/cargo-tree.html),
[PlantUML](https://plantuml.com/component-diagram).
