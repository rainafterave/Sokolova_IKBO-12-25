# Эмулятор командной оболочки UNIX

Практическая работа №1 по дисциплине «Конфигурационное управление».
**Вариант 23, этапы 1-4.**

Графическое приложение на Python и Tkinter. Пользователь вводит команды
в строке терминала; в окне отображаются приглашение, введенная команда
и результат. Заголовок `Эмулятор - [username@hostname]` использует
реальное имя пользователя и имя компьютера.

Виртуальная файловая система загружается из CSV. Каталоги и содержимое
файлов хранятся в оперативной памяти. Исходный CSV открывается только
для чтения; виртуальные файлы на диск не извлекаются.

## Быстрый запуск в Windows

Требуется **Python 3.10+ с Tkinter**. Сторонние библиотеки и сборка
не нужны. При установке Python для Windows должен быть выбран компонент
`tcl/tk and IDLE`. Проверка Tkinter: `py -3 -m tkinter`.

Все команды ниже выполняются из папки `pract/pract1` в PowerShell.
Из корня репозитория сначала перейдите в нее:

```powershell
cd pract/pract1
```

```powershell
.\run.bat
```

По умолчанию открывается GUI этапа 4 с `vfs-samples/deep.csv`.
Запуск с выводом демонстрационных команд и последующим ручным вводом:

```powershell
.\run.bat --vfs vfs-samples/deep.csv --script scripts/interactive.txt
```

`run.bat` использует `py -3`, а при отсутствии launcher — `python`.
Можно выбрать интерпретатор явно:

```powershell
$env:PYTHON_EXE = 'C:\path\to\python.exe'
.\run.bat
```

Прямой запуск также поддерживается:

```powershell
py -3 src/main.py --vfs vfs-samples/deep.csv
py -3 -m src.main --script scripts/interactive.txt
```

На Linux/macOS: `sh run.sh` (нужен Python 3.10+ и системный Tkinter;
например, пакет `python3-tk` в Debian/Ubuntu).

## Выполненные этапы

| Этап | Реализация | Демонстрация |
|---|---|---|
| 1. REPL | GUI, данные ОС в заголовке, кавычки, заглушки `ls`/`cd`, `exit`, ошибки | `--stage 1 --script scripts/stage1.txt` |
| 2. Конфигурация | `--vfs`, `--script`, вывод параметров, сценарий до первой ошибки | `--stage 2 --script scripts/stage2.txt` |
| 3. VFS | CSV, base64, дерево в памяти, три примера VFS и навигация | `--stage 3 --script scripts/stage3.txt` |
| 4. Основные команды | `ls`, `cd`, `uptime`, `history`, `date`, сценарии успеха и ошибок | `--script scripts/stage4.txt` |

`--stage` позволяет воспроизвести ранние этапы без дублирования исходников.
В этапах 1-2 VFS не читается, `ls` и `cd` печатают свои имена и аргументы.
На этапе 3 подключены VFS и навигация для проверки ее содержимого;
на этапе 4 доступен полный набор команд.
Если демонстрационный сценарий заканчивается `exit`, окно закроется.
Для ручной проверки используйте запуск без `--script` или
`scripts/interactive.txt`.

Этап 5 в объем этой работы не входит.
Коммиты пока не создавались по просьбе пользователя. Переключатель
`--stage` демонстрирует поведение этапов; он не заменяет историю Git.

## Параметры командной строки

| Параметр | Значение и поведение |
|---|---|
| `--vfs PATH` | Физический путь к CSV. По умолчанию `vfs-samples/deep.csv` из папки проекта |
| `--script PATH` | Стартовый сценарий UTF-8; по умолчанию не задан |
| `--stage N` | Этап 1, 2, 3 или 4; по умолчанию 4 |
| `--headless` | Выполнение сценария без GUI для автоматических проверок; требует `--script` |
| `-h`, `--help` | Справка, без открытия окна |

Приложение обычно запускается с GUI. `--headless` — дополнительный режим
проверки, в котором используются тот же парсер, VFS и обработчики команд.
После окончания сценария этот режим завершает процесс. Интерактивный
ввод реализован в графическом окне.

Относительные явно заданные пути отсчитываются от рабочей папки запуска;
`run.bat` и `run.sh` сначала переходят в корень проекта. Физические пути
с пробелами необходимо заключать в кавычки:

```powershell
.\run.bat --vfs "C:\Учеба\Моя VFS.csv" --script "C:\Учеба\Старт.txt"
```

При успешном запуске в окне или выводе автоматического режима показаны
все итоговые параметры:

```text
[config] vfs = C:\project\vfs-samples\deep.csv
[config] script = не задан
[config] stage = 4
[config] headless = False
```

Коды возврата: `0` — успешное завершение; `1` — ошибка загрузки или
ошибка команды в сценарии режима `--headless`; `2` — неверные параметры
командной строки. В GUI ошибка команды отображается в журнале,
после нее можно продолжить ввод.

## Команды

| Команда | Поведение |
|---|---|
| `ls [-a] [-l] [--] [PATH ...]` | Отсортированные имена прямых потомков. Без пути — текущий каталог. Для файла — его имя. Каталоги помечены `/` |
| `ls -a` | Включает скрытые имена, начинающиеся с точки. Синтетические `.` и `..` в список не добавляются |
| `ls -l`, `ls -al` | Тип `dir`/`file`, размер содержимого в байтах, имя; размер каталога — 0 |
| `ls -- PATH` | `--` завершает разбор опций; можно указывать несколько путей |
| `cd [PATH]` | Переход в каталог; без аргумента — корень VFS. Поддерживаются абсолютные и относительные пути, `.` и `..` |
| `uptime` | Время работы текущего экземпляра эмулятора: `up D days, HH:MM:SS` |
| `history [N]` | Вся история с нумерацией либо последние N команд. `history 0` ничего не выводит |
| `date [-u] [+FORMAT]` | Реальные дата и время ОС; `-u` выбирает UTC. По умолчанию используется локальный часовой пояс |
| `exit` | Закрывает окно или завершает сценарий. Аргументы не принимаются |

Примеры переносимых форматов даты: `date +%Y-%m-%d`,
`date "+%Y-%m-%d %H:%M:%S"`, `date -u +%H:%M:%S`.
Форматирование использует `datetime.strftime`; дополнительные спецификаторы
зависят от платформы. `date` не меняет системное время.

Время `uptime` отсчитывается монотонными часами от создания оболочки.
`history` включает команды сценария, ошибки и текущий вызов `history`;
пустые строки и комментарии сценария в историю не попадают.

Пути внутри VFS всегда используют `/`, включая запуск на Windows.
Выход выше `/` оставляет пользователя в корне; ошибка `cd` не меняет
текущий каталог. Файлы реальной ОС через команды оболочки недоступны.

Парсер поддерживает одинарные и двойные кавычки, пустые аргументы,
экранирование пробелов обратной косой чертой и соседние фрагменты строк:

```text
cd "/home/student/My Documents"
ls '/home/student/My Documents/read me.txt'
ls /home/student/My\ Documents
```

Переменные окружения, конвейеры, перенаправления и запуск программ ОС
не реализованы. Дополнительные флаги команд вне таблицы дают ошибку.

## Управление окном

- Enter или кнопка «Выполнить» исполняет строку.
- Стрелки вверх/вниз перебирают историю ввода.
- Ctrl+C в строке ввода очищает ее.
- Журнал диалога можно выделять и копировать, но нельзя редактировать.
- `exit` и кнопка закрытия окна завершают работу.

## Формат CSV и представление VFS

Файл UTF-8 (допускается BOM) с точным заголовком `path,type,data`.
Поля с запятыми заключаются в кавычки по правилам CSV.

```csv
path,type,data
/,dir,
/home/student,dir,
/home/student/hello.txt,file,SGVsbG8K
/empty,dir,
```

- `path` — уникальный абсолютный POSIX-путь. Компоненты `.` и `..`,
  повторные разделители и завершающий `/` кроме корня не допускаются.
- `type=dir` — каталог с пустым полем `data`.
- `type=file` — файл; `data` содержит base64 его байтов. Одинаковый способ
  используется для текста и двоичных данных. В примере закодирован `Hello\n`.
- Отсутствующие родительские каталоги создаются в памяти автоматически.
  Порядок строк произвольный. Пустые каталоги задаются явно.
- Нулевой файл представлен `file` с пустым `data`.
- Повтор пути, файл вместо родителя, неизвестный тип, поврежденный base64,
  неверный заголовок или количество полей приводят к ошибке загрузки.

VFS хранится как словарь `абсолютный путь -> Node(kind, data)`.
`Node.data` — байты, полученные из base64. Физический CSV читается один раз
при запуске, навигация и листинг работают только со словарем в памяти.

| Пример | Содержимое |
|---|---|
| `vfs-samples/minimal.csv` | Только корневой каталог — минимальная VFS |
| `vfs-samples/several.csv` | Четыре файла, включая пустой |
| `vfs-samples/deep.csv` | Несколько уровней до `/home/student/docs/drafts/todo.txt`, пустой каталог, скрытый и двоичный файлы, пути с пробелами |

CSV — текстовые исходные данные, поэтому примеры включены в репозиторий.
Архивы и отдельные двоичные файлы не требуются.

## Стартовые сценарии и обработка ошибок

Сценарий — текст UTF-8, одна команда на строку. Пустые строки и строки,
начинающиеся с `#` после пробелов, пропускаются. Комментарии в конце
команды не обрабатываются. Каждая команда выводится с текущим приглашением,
после нее — результат. **При первой ошибке сценарий останавливается**,
номер проблемной строки показывается в журнале. В GUI после этого можно
вводить команды вручную. `exit` прекращает выполнение оставшихся строк.

Успешные сценарии этапов: `scripts/stage1.txt` — `scripts/stage4.txt`.
Для ошибок используются отдельные сценарии в `scripts/errors/`, поскольку
по требованию варианта сценарий не может продолжаться после первой ошибки.
Строка `date +SHOULD_NOT_RUN` после ошибки служит контрольной:
она не должна быть выполнена и даже не должна появиться в диалоге.

| Сценарий ошибки | Что проверяет |
|---|---|
| `unknown.txt` | Неизвестная команда |
| `quotes.txt` | Незакрытые кавычки |
| `cd_args.txt`, `cd_file.txt`, `cd_missing.txt` | Неверное число аргументов, переход в файл и отсутствующий каталог |
| `ls_missing.txt`, `ls_option.txt` | Отсутствующий путь и неподдерживаемая опция |
| `uptime_args.txt` | Лишний аргумент |
| `history_args.txt` | Неверное число команд |
| `date_args.txt` | Неверный формат аргументов |
| `exit_args.txt` | Лишний аргумент; оболочка не закрывается |

Пример ручной проверки в GUI:

```text
student@host:/$ cd "/home/student/My Documents"
student@host:/home/student/My Documents$ ls
read me.txt
student@host:/home/student/My Documents$ cd /missing
нет такого файла или каталога: /missing
student@host:/home/student/My Documents$ uptime
up 0 days, 00:00:12
student@host:/home/student/My Documents$ history 2
    3  uptime
    4  history 2
```

## Проверки и демонстрация

Автоматические тесты стандартной библиотеки (без установки зависимостей):

```powershell
py -3 -m unittest discover -s tests -v
```

Отдельная проверка настоящих виджетов Tkinter (нужен графический сеанс):

```powershell
py -3 -m unittest tests.gui_smoke -v
```

Проверяются кавычки и экранирование, заголовок, все команды, ошибка `cd`
без изменения состояния, история и форматы даты, двоичные данные,
глубокая вложенность, конфликты CSV, неизменность исходного файла,
физические пути с пробелами, все демонстрационные сценарии, остановка
на первой ошибке, настройки и коды возврата. GUI-проверки дополнительно
проверяют ручной ввод после ошибки сценария, журнал и клавиши истории.

Скрипты настоящей ОС Windows с вызовами эмулятора:

```powershell
.\tests\test_config.bat
.\tests\test_vfs.bat
.\tests\test_commands.bat
```

Они возвращают `0` при успехе; сообщения об ожидаемых ошибках являются
частью проверки. Для демонстрации разных настроек и VFS в окнах:

```powershell
.\scripts\demo_config.bat
.\scripts\demo_vfs.bat
```

Каждый следующий запуск начинается после закрытия предыдущего окна.
`demo_config.bat` проверяет запуск без параметров, только с `--vfs`,
только с `--script` и с обоими параметрами. `demo_vfs.bat` открывает
минимальную VFS, несколько файлов и глубокую иерархию.

## Структура и назначение функций

```text
pract/pract1/
|-- README.md
|-- run.bat, run.sh
|-- src/             исходники приложения
|-- scripts/         сценарии этапов, ошибок и демонстрации Windows
|-- tests/           автоматические тесты и проверки Windows
`-- vfs-samples/     три исходных CSV
```

Общий `.gitignore` находится в корне репозитория и действует также
на вложенную папку практической работы.

| Модуль | Классы и функции |
|---|---|
| `config.py` | `Config` хранит настройки; `debug_lines()` формирует отладочный вывод; `parse_args()` разбирает и проверяет параметры |
| `parser.py` | `parse()` возвращает команду и аргументы с учетом кавычек; пустой ввод возвращает `(None, [])` |
| `vfs.py` | `Node` хранит тип и байты, `VFSError` сообщает ошибки, `VFS` хранит узлы |
| `VFS.from_csv()` | Читает и проверяет исходный CSV |
| `VFS.resolve()` | Разрешает абсолютный/относительный путь по компонентам |
| `VFS.children()` | Возвращает отсортированные имена прямых потомков |
| `VFS._add_row()`, `_decode()`, `_ensure_parents()` | Проверяют запись, декодируют данные и создают родителей в памяти |
| `shell.py` | `Shell` хранит путь, команды, историю, данные ОС и время запуска; `CommandError` обозначает ошибку команды |
| `Shell.execute()` | Разбирает строку, записывает историю, вызывает команду, возвращает `(успех, вывод)` |
| `Shell.title`, `Shell.prompt` | Формируют заголовок и приглашение |
| `Shell.cmd_*()` | Реализуют одноименные команды из таблицы выше |
| `Shell._one_arg()`, `_no_args()` | Проверяют количество аргументов |
| `Shell._ls_options()`, `_listing()`, `_entry()` | Разбирают опции и формируют листинг |
| `scripts.py` | `read_script()` читает команды с номерами строк; `run_script()` исполняет их до ошибки или `exit` |
| `gui.py` | `EmulatorWindow` создает графический терминал |
| `EmulatorWindow.emit()`, `start()`, `submit()` | Выводят текст, запускают сценарий и принимают ручной ввод |
| `EmulatorWindow.refresh()`, `recall()`, `cancel()`, `close()` | Обновляют приглашение, перебирают историю, очищают ввод и закрывают окно |
| `main.py` | `prepare()` читает данные до запуска окна; `main()` выбирает GUI/проверку и возвращает код завершения |
